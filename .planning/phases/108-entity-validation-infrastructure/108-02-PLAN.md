Create `packages/entities/src/__tests__/id-constants.test.ts` with these validation checks:

**Import side-effects first:**
```typescript
import '@into-the-void/entities'; // Side-effect: registers all entities
```

Then imports:
```typescript
import { describe, it, expect } from 'vitest';
import { ALL_ENTITIES, ENTITY_IDS } from '../definitions';
import { EntityRegistry } from '../registry';
```

**snake_case regex:**
```typescript
const SNAKE_CASE_RE = /^[a-z][a-z0-9]*(_[a-z0-9]+)*$/;
```

**Test group 1: Constant → Entity direction**
Use `it.each` over `Object.entries(ENTITY_IDS)`. For each `[constName, entityId]`:
- Assert `EntityRegistry.has(entityId)` is true
- Error message: `ENTITY_IDS.${constName} maps to "${entityId}" but no entity with that ID exists in EntityRegistry. Either add the entity definition or remove the constant`

**Test group 2: Entity → Constant direction**
Use `it.each` over ALL_ENTITIES. For each entity:
- Assert that `Object.values(ENTITY_IDS).includes(entity.id)` is true
- Error message: `Entity "${entity.id}" (${entity.displayName}) is registered but has no matching ENTITY_IDS constant. Add it to ENTITY_IDS in packages/entities/src/definitions/index.ts`

**Test group 3: snake_case naming convention**
Use `it.each` over `Object.entries(ENTITY_IDS)`. For each `[constName, entityId]`:
- Assert `entityId` matches `SNAKE_CASE_RE`
- Error message: `ENTITY_IDS.${constName} value "${entityId}" is not valid snake_case. Use format like "creature_void_crawler"`

**Test group 4: ENTITY_IDS constant name matches entity ID pattern**
Use `it.each` over `Object.entries(ENTITY_IDS)`. For each `[constName, entityId]`:
- The constant name (UPPER_SNAKE) should match the entity ID (lower_snake) when lowercased
- Assert `constName.toLowerCase() === entityId`
- Error message: `ENTITY_IDS.${constName} (lowered: "${constName.toLowerCase()}") does not match its value "${entityId}". The constant name should be the UPPER_CASE version of the entity ID`

**Test group 5: No duplicate entity IDs**
Collect all entity IDs from ALL_ENTITIES. Assert the array length equals Set size:
```typescript
const ids = ALL_ENTITIES.map(e => e.id);
const uniqueIds = new Set(ids);
const duplicates = ids.filter((id, i) => ids.indexOf(id) !== i);
expect(duplicates).toEqual([]);
// Error: `Duplicate entity IDs found: ${duplicates.join(', ')}`
```

All tests MUST use hard `expect()` assertions. If the current codebase has violations, fix them to establish a clean baseline per CONTEXT.md.

  <action>
Create `packages/entities/src/__tests__/harvest-yields.test.ts` with these validation checks:

**Import side-effects first:**
```typescript
import '@into-the-void/items';    // Side-effect: registers all items in ItemRegistry
import '@into-the-void/entities'; // Side-effect: registers all entities
```

Then imports:
```typescript
import { describe, it, expect } from 'vitest';
import { ALL_ENTITIES } from '../definitions';
import { ItemRegistry } from '@into-the-void/items';
import type { PlantDefinition, MineralDefinition } from '../types';
```

**Filter by entity class:**
```typescript
const allPlants = ALL_ENTITIES.filter(
  (e): e is PlantDefinition => e.entityClass === 'plant'
);
const allMinerals = ALL_ENTITIES.filter(
  (e): e is MineralDefinition => e.entityClass === 'mineral'
);
```

**Test group 1: Every plant harvestYield itemId exists in ItemRegistry**
Use `it.each` over allPlants. For each plant:
- For each entry in `plant.harvestYield`:
  - Assert `ItemRegistry.has(entry.itemId)` is true
  - Error message: `Plant "${plant.id}" harvestYield references item "${entry.itemId}" which does not exist in ItemRegistry. Add it in packages/items/src/definitions/ or fix the reference`

**Test group 2: Every mineral miningYield itemId exists in ItemRegistry**
Use `it.each` over allMinerals. For each mineral:
- For each entry in `mineral.miningYield`:
  - Assert `ItemRegistry.has(entry.itemId)` is true
  - Error message: `Mineral "${mineral.id}" miningYield references item "${entry.itemId}" which does not exist in ItemRegistry. Add it in packages/items/src/definitions/ or fix the reference`

**Test group 3: Plant harvest yields don't reference equipment items (type correctness)**
Use `it.each` over allPlants. For each plant:
- For each entry in `plant.harvestYield`:
  - If `ItemRegistry.has(entry.itemId)`, get the item
  - Assert item category is NOT 'suit', 'tool', or 'module'
  - Error message: `Plant "${plant.id}" harvestYield references "${entry.itemId}" which is a ${item.category} — plants should not drop equipment. Use 'world' or 'reagent' category items`

**Test group 4: Mineral mining yields don't reference equipment items (type correctness)**
Same as group 3 but for minerals' miningYield.

**Test group 5: Harvest yield value ranges are valid**
For each plant, for each harvestYield entry:
- Assert `entry.chance > 0 && entry.chance <= 1.0` — chance is a valid probability
- Assert `entry.minAmount >= 1` — can't harvest 0
- Assert `entry.maxAmount >= entry.minAmount` — max must be >= min
- Error messages should name the plant/mineral and the specific bad entry

For each mineral, same checks on miningYield.

**Test group 6: Every plant has at least one harvest yield entry**
For each plant:
- Assert `plant.harvestYield.length > 0`
- Error message: `Plant "${plant.id}" has no harvestYield entries — harvesting it would produce nothing`

**Test group 7: Every mineral has at least one mining yield entry**
For each mineral:
- Assert `mineral.miningYield.length > 0`
- Error message: `Mineral "${mineral.id}" has no miningYield entries — mining it would produce nothing`

All tests MUST use hard `expect()` assertions. If the current codebase has violations, fix the entity or item definitions to establish a clean baseline per CONTEXT.md.
