Create `packages/entities/src/__tests__/loot-tables.test.ts` with these validation checks:

**CRITICAL: Import side-effects first.** The very first lines must import the package roots to trigger registry population:
```typescript
import '@into-the-void/items';    // Side-effect: registers all items in ItemRegistry
import '@into-the-void/entities'; // Side-effect: registers all entities in EntityRegistry
```

Then import what you need:
```typescript
import { describe, it, expect } from 'vitest';
import { ALL_ENTITIES, ENTITY_IDS } from '../definitions';
import { CREATURE_LOOT_TABLES } from '@into-the-void/game-logic';
import { ItemRegistry } from '@into-the-void/items';
import type { CreatureDefinition } from '../types';
```

**Filter creatures from ALL_ENTITIES:**
```typescript
const allCreatures = ALL_ENTITIES.filter(
  (e): e is CreatureDefinition => e.entityClass === 'creature'
);
```

**Test group 1: Every creature has a loot table entry**
Use `it.each` over allCreatures. For each creature:
- Check `CREATURE_LOOT_TABLES.has(creature.lootTableId)` is true
- Error message: `Creature "${creature.id}" has no CREATURE_LOOT_TABLES entry (expected key: "${creature.lootTableId}"). Add it in packages/game-logic/src/loot/creature-loot.ts`

**Test group 2: Every loot table entry has at least one item with positive drop chance**
Use `it.each` over allCreatures (only those with loot tables). For each:
- Get loot entries via `CREATURE_LOOT_TABLES.get(creature.lootTableId)`
- Assert entries exist and at least one entry has `chance > 0`
- Error message: `Loot table "${creature.lootTableId}" for creature "${creature.id}" has no items with positive drop chance — creature would drop nothing`

**Test group 3: Every loot table item reference exists in ItemRegistry**
Use `it.each` over allCreatures (only those with loot tables). For each creature:
- Get all loot entries
- For each loot entry, assert `ItemRegistry.has(entry.itemId)` is true
- Error message: `Loot table "${creature.lootTableId}" references item "${entry.itemId}" which does not exist in ItemRegistry. Check packages/items/src/definitions/ for valid item IDs`

**Test group 4: No orphaned loot tables (reverse check)**
Collect all lootTableIds from allCreatures into a Set. Iterate `CREATURE_LOOT_TABLES.keys()`. Assert each key exists in the creature set.
- Error message: `CREATURE_LOOT_TABLES has entry "${key}" but no creature references it as its lootTableId. Remove it or add the creature definition`

All tests MUST use hard `expect()` assertions, no `console.warn`. Any failure is a test failure.

**Test group 1: Every spawnable entity (with biomes) has at least one BIOME_SPAWN_CONFIGS entry**
For each entity in ALL_ENTITIES that has `biomes.length > 0`:
- Collect all entity IDs referenced across ALL biome spawn configs (creatures, minerals, plants, artifacts arrays)
- Assert the entity's id appears in at least one biome config
- Error message: `Entity "${entity.id}" declares biomes [${entity.biomes}] but is not referenced in any BIOME_SPAWN_CONFIGS entry. Add it to the spawn config for its biome(s) in packages/world-gen/src/generation/spawn.ts`

**Test group 2: Every entity ID in BIOME_SPAWN_CONFIGS references a registered entity**
For each biome in BIOME_SPAWN_CONFIGS:
- For each entity reference in creatures/minerals/plants/artifacts arrays:
  - Assert `EntityRegistry.has(ref.id)` is true
  - Error message: `BIOME_SPAWN_CONFIGS["${biome}"].${category} references entity "${ref.id}" which does not exist in EntityRegistry. Check packages/entities/src/definitions/ for valid entity IDs`

**Test group 3: No biome has completely empty entity lists**
For each biome in BIOME_SPAWN_CONFIGS:
- Assert that `creatures.length + plants.length + minerals.length > 0` (at least one spawnable entity type)
- Error message: `Biome "${biome}" has no creatures, plants, or minerals in its spawn config — it would be completely lifeless`

**Test group 4: Spawn config value ranges are valid**
For each biome in BIOME_SPAWN_CONFIGS:
- For each creature entry: assert `weight > 0`, `minLevel >= 1`, `maxLevel >= minLevel`
- For each mineral entry: assert `weight > 0`, `rarity >= 1`
- For each plant entry: assert `weight > 0`
- For each artifact entry: assert `weight > 0`
- Assert density values are all > 0: `creatureDensity`, `mineralDensity`, `plantDensity`
- Error message should name the biome and the specific invalid entry

All tests MUST use hard `expect()` assertions. If the current codebase has violations (e.g., entities declaring biomes but missing from spawn configs), fix the entity definitions or spawn configs to make the baseline clean. The CONTEXT.md mandates "fix all existing violations — no allowlists."
