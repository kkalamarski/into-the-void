Update the handleMove method in GameGateway to:

1. Update the MessageBody type to include sequence:
```typescript
@MessageBody() data: { direction: Direction; sequence?: number }
```

2. Add rate limiting check at start of handler (after getting player):
```typescript
const player = this.playerService.getPlayerBySocket(client.id);
if (!player) return;

const now = Date.now();
const lastMoveTime = this.playerService.getLastMoveTime(player.id);

// Rate limit: minimum 140ms between moves (150ms client delay - 10ms tolerance)
if (now - lastMoveTime < 140) {
  client.emit('error', {
    code: 'E-0006',
    message: 'Movement too fast',
    lastProcessedInput: data.sequence,
  });
  return;
}

this.playerService.setLastMoveTime(player.id, now);
```

3. Update the successful same-zone movement emit to include lastProcessedInput:
```typescript
// Same zone movement
this.server.to(result.zoneId!).emit('player:moved', {
  playerId: result.playerId,
  position: result.position,
  lastProcessedInput: data.sequence,
});
```

4. Update the error emit for blocked movement to include lastProcessedInput:
```typescript
client.emit('error', {
  code: 'MOVEMENT_BLOCKED',
  message: result.error || 'Movement blocked',
  lastProcessedInput: data.sequence,
});
```

5. For zone transitions, include sequence in the zone:state context (the client will reset prediction state on zone change anyway, but for completeness):
The existing zone transition code sends zone:state which triggers a prediction reset on client.

Key points:

- Always echo sequence number back, even on errors
