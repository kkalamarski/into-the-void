<objective>
Fix invisible collision walls at chunk and zone boundaries so players move freely across the entire world.

Purpose: The collision callback in both the client (`setCollisionMap`) and server (`MovementService.tick`) uses a single zone's collision array with `?? true` fallback for out-of-bounds indices. When the player's AABB hitbox corners map to tile coordinates outside `[0, ZONE_SIZE)`, the fallback treats them as solid walls. The fix is to route collision lookups through multi-chunk resolvers that find the correct chunk for any world tile coordinate.

Output: Seamless collision resolution across chunk and zone boundaries on both client and server.
</objective>

The root cause is that `PixelMovementController` calls `isSolid(tileX, tileY)` where tileX/tileY are derived from the player's pixel position via `Math.floor(px / TILE_SIZE_PX)`. These are **zone-local** tile coordinates. When the player's AABB hitbox extends past a zone boundary, the corners produce tile coordinates outside `[0, ZONE_SIZE)` (negative or >= 64), and the `?? true` fallback treats them as solid walls.

The fix: `isWorldTileBlocked(worldX, worldY)` already correctly resolves any world tile coordinate to the right chunk. But the collision callback receives zone-local tile coordinates (relative to the current zone's origin), not world tile coordinates. The callback must convert zone-local to world tile coordinates before calling `isWorldTileBlocked`.

**Step 1: Modify `setCollisionMap` method (around line 2425)**

Replace the collision callback to convert zone-local tile coordinates to world tile coordinates and use `isWorldTileBlocked`:

```typescript
setCollisionMap(collisionMap: boolean[][]): void {
  this.collisionMap = collisionMap;
  // Set collision callback for pixel movement — uses cross-chunk lookup
  if (this.pixelMovement) {
    // Capture current zone offset for converting zone-local → world coordinates
    const zoneCoords = this.parseZoneCoords(this.currentZoneId);
    const offsetX = zoneCoords.x * ZONE_SIZE;
    const offsetY = zoneCoords.y * ZONE_SIZE;
    this.pixelMovement.setCollisionCallback((tx, ty) => {
      return this.isWorldTileBlocked(offsetX + tx, offsetY + ty);
    });
  }
}
```

**Step 2: Modify `loadZoneFromState` method (around line 1019-1024)**

Replace the direct collisionMap lookup with the same cross-chunk approach:

```typescript
// Set collision callback if collision map is available
if (chunkData.collisions) {

}
```

This replaces the inline callback with a call to the updated `setCollisionMap`, which now routes through `isWorldTileBlocked`.

**Step 3: Update `isWorldTileBlocked` to handle the case where ChunkManager is not yet initialized**

The method already returns `true` (blocked) when `chunkManager` is null. This is correct — it means collision checking won't crash, it just conservatively blocks. No change needed here, but verify the method does NOT have stale references.

**Why this works:** The player's pixel position px=10 with hitbox half-width=32 produces a left corner at px=-22. `Math.floor(-22 / 128) = -1` as tileX (zone-local). Adding the zone offset converts this to the correct world tile in the adjacent zone. `isWorldTileBlocked` then looks up the adjacent chunk (which is already loaded in the 3x3 grid) and returns the real collision value.

**Edge case — unloaded chunks:** If the adjacent chunk hasn't loaded yet, `isWorldTileBlocked` returns `true` (blocked). Per user decision, "movement is never blocked for loading" — however, the collision being conservative for a brief moment while chunks load is acceptable because the 3x3 grid loads adjacents proactively. The player would only hit this if they moved faster than network latency, which is extremely unlikely. Do NOT change this fallback — it prevents walking into void.

The server-side `MovementService.tick()` has the same bug: it uses `chunk.collisions[ty]?.[tx] ?? true` where `ty` and `tx` are zone-local tile coordinates derived from the player's pixel position. When the hitbox extends past the zone boundary, out-of-bounds coordinates are treated as solid.

The server also needs a cross-zone collision lookup, but it does not have a `ChunkManager` — it has `ZonesService.getChunkSync()`.

**Step 1: Add `isWorldTileBlocked` helper to `ZonesService` (zones.service.ts)**

Add a synchronous method that mirrors the client's `isWorldTileBlocked` logic:

```typescript
/**
 * Check if a world tile coordinate is blocked.
 * Resolves the correct zone and looks up local collision data.
 * Returns true (blocked) if the zone is not loaded (conservative).
 */
isWorldTileBlocked(worldX: number, worldY: number): boolean {
  const zoneX = Math.floor(worldX / ZONE_SIZE);
  const zoneY = Math.floor(worldY / ZONE_SIZE);
  const zoneId = `z_${zoneX}_${zoneY}`;

  const chunk = this.getChunkSync(zoneId);
  if (!chunk?.collisions) return true; // Zone not loaded = blocked

  const localX = ((worldX % ZONE_SIZE) + ZONE_SIZE) % ZONE_SIZE;
  const localY = ((worldY % ZONE_SIZE) + ZONE_SIZE) % ZONE_SIZE;

  return chunk.collisions[localY]?.[localX] ?? true;
}
```

Import `ZONE_SIZE` from `@into-the-void/shared-types` at the top of `zones.service.ts` if not already imported.
