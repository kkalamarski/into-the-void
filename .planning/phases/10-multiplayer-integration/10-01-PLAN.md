Integrate remote players into the depth sorting system for correct isometric rendering.

Purpose: Remote players currently render at correct positions but are NOT included in the throttled depth sorting updates. When remote players move, their depth is updated in the tween onComplete callback but they're missing from the DepthSorter.update() entity map, causing potential depth inconsistencies with entities during movement.

Output: Remote players sorted by depth alongside entities, markDirty called on movement.
</objective>

  <files>apps/web/src/game/scenes/WorldScene.ts</files>
  <action>
Update WorldScene to include remote players in depth sorting:

1. In `movePlayer()` method (around line 514), add a call to mark the player dirty for depth sorting BEFORE creating the tween:
   ```typescript
   if (this.depthSorter) {
     this.depthSorter.markDirty(playerId);
   }
   ```
   This ensures the DepthSorter knows to recalculate depth during the throttled update cycle.

2. In `update()` method (around line 240), modify the depth sorter update to include both entities AND remote players:
   ```typescript
   // Throttled depth sorting - include entities AND remote players
   if (this.depthSorter && this.isoTransform) {
     // Create combined map of all depth-sortable objects
     const allContainers = new Map<string, Phaser.GameObjects.Container>();

     // Add entities
     this.entitySprites.forEach((container, id) => {
       allContainers.set(id, container);
     });

     // Add remote players (use plain ID - matches markDirty call)
     this.playerSprites.forEach((sprite, id) => {
       allContainers.set(id, sprite as unknown as Phaser.GameObjects.Container);
     });

     this.depthSorter.update(time, allContainers, this.isoTransform);
   }
   ```
   Note: Use plain player ID (not prefixed) to match the markDirty(playerId) call. Entity IDs and player IDs are UUIDs so collision is not a practical concern.

Why this matters: Without this integration, remote players may briefly render at incorrect depths during movement (their depth updates in tween onComplete, but the DepthSorter's throttled updates don't include them). This causes subtle z-fighting during rapid movement sequences.
