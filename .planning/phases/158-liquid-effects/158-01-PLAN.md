1. Create `packages/shared-types/src/game/liquid.ts` with:
   - `LiquidEffectState` interface: `{ entityId: string, liquidTileId: string, speedMultiplier: number, damagePerTick: number, healPerTick: number, lastTickAt: number, enteredAt: number }`
   - `LiquidDamagePayload`: `{ entityId: string, damage: number, health: number, maxHealth: number, liquidTileId: string }`
   - `LiquidHealPayload`: `{ entityId: string, heal: number, health: number, maxHealth: number, liquidTileId: string }`
   - `LiquidUpdatePayload`: `{ active: boolean, liquidTileId?: string, displayName?: string, color?: string, speedMultiplier?: number, damagePerTick?: number, healPerTick?: number }`
   - Export all types.

2. Add `export * from './liquid';` to `packages/shared-types/src/game/index.ts`.

3. Create `apps/game-server/src/game/liquid-effect.service.ts` following HazardService pattern:
   - `@Injectable()` class `LiquidEffectService`
   - Private `liquidStates: Map<string, LiquidEffectState>` for per-entity tracking (both players and creatures)
   - `setServer(server: Server)` — store Socket.IO reference
   - `onPlayerDisconnect(playerId: string)` — clean up state

   **Core method: `processLiquidTick(zoneId: string)`** — called from AiService.runZoneTick():
   - Get all players in zone via PlayerService.getPlayersInZone()
   - For each player: compute current tile from `Math.floor(player.px / TILE_SIZE_PX)` for both X and Y
   - Look up the zone's ChunkData via ZonesService.getChunkSync(zoneId) — read `liquidTiles[tileY][tileX]`
   - If player is on a liquid tile:
     - Look up TileDefinition from TileRegistry.get(liquidTileId) to get liquidEffect
     - If no existing state → create new LiquidEffectState with `enteredAt: Date.now(), lastTickAt: 0`
     - If existing state AND enough time elapsed (use 2000ms tick interval — 2 seconds):
       - If `damagePerTick > 0`: apply damage to player.health (cap at 0), emit `liquid:damage` event to player, emit `player:health` for HUD update
       - If `healPerTick > 0`: apply heal to player.health (cap at maxHealth), emit `liquid:heal` event to player, emit `player:health` for HUD update
       - Update `lastTickAt` to now
     - Emit `liquid:update` with `active: true` on first entry
   - If player is NOT on liquid but has active state → clear state, emit `liquid:update` with `active: false`

   **Creature processing** in same `processLiquidTick()`:
   - Get zone entities from ZonesService.getZoneEntities(zoneId) (already used by AiService)
   - For each creature entity with position: compute tile, check liquidTiles overlay
   - Apply same damage/heal logic to creature's health field
   - Track creature states in same Map using entity.id as key
   - NO socket events needed for creature damage (creatures don't have individual client connections) — the entity:batch update from AiService already broadcasts health changes

   **Speed multiplier accessor: `getSpeedMultiplier(entityId: string): number`**
   - Return the speedMultiplier from active LiquidEffectState, or 1.0 if no state

   **For open-world zones (zoneId starts with "z_"):**
   - Use ZonesService.getChunkSync() which returns the zone's chunk data including liquidTiles
   - Tile coordinates need zone-local conversion: for open-world zones with "z_X_Y" format, player px/py are already zone-local (movement stays within a zone's coordinate space)

   Inject: `PlayerService`, `ZonesService`. Import `TILE_SIZE_PX` from `@into-the-void/game-logic`. Import TileRegistry from `@into-the-void/tiles` (check how it's imported in existing services — likely the tiles package exports a registry or use ALL_LIQUID_TILES to build a local map).

   **IMPORTANT:** Check how TileRegistry is actually imported in the game-server. If there is no TileRegistry, build a simple local Map from ALL_LIQUID_TILES at module init time, keyed by tile id.

   The tick must be synchronous (no async calls) — same constraint as HazardService. All reads from Map and ChunkData are synchronous.
