1. Create STAT_DISPLAY_ORDER constant in apps/web/src/ui/constants.ts (alongside RARITY_COLORS):
```typescript
import type { CharacterStats } from '@into-the-void/shared-types';

export const STAT_DISPLAY_ORDER: Array<{ key: keyof CharacterStats; label: string }> = [
  { key: 'durability', label: 'Durability' },
  { key: 'toughness', label: 'Toughness' },
  { key: 'power', label: 'Power' },
  { key: 'haste', label: 'Haste' },
  { key: 'vigor', label: 'Vigor' },
  { key: 'recovery', label: 'Recovery' },
  { key: 'perception', label: 'Perception' },
  { key: 'resilience', label: 'Resilience' },
];
```

2. Extend StatsState interface in statsStore.ts:
- Add `levelUpDeltas: Partial<CharacterStats> | null` state field
- Add `clearLevelUpDeltas: () => void` action

3. Modify setStats action to detect level-up:
- Import STAT_DISPLAY_ORDER from '../ui/constants'
- In setStats, before assigning payload to state.stats:
  - If state.stats is not null (previous payload exists):
    - Compare payload.base[key] vs state.stats.base[key] for each key in STAT_DISPLAY_ORDER
    - For any key where payload.base[key] > state.stats.base[key], add delta to a deltas object
    - If deltas has any keys, set state.levelUpDeltas = deltas
- Then assign state.stats = payload

4. Add clearLevelUpDeltas action:
```typescript
clearLevelUpDeltas: () =>
  set((state) => {
    state.levelUpDeltas = null;
  }),
```

Critical: Compare base stats only (not total) — equipment changes affect total but not base. Level-up only affects base.

Check that constants.ts exports STAT_DISPLAY_ORDER.
  </verify>
