  <action>
Create `PixelMovementController` class that replaces the tile-step `MovementController` for local player movement.

**Class state:**
- `private px: number` — current predicted pixel X
- `private py: number` — current predicted pixel Y
- `private zoneId: string` — current zone
- `private inputSequence: number = 0` — monotonically increasing counter
- `private pendingInputs: Array<{ sequence: number; keys: number; vx: number; vy: number; px: number; py: number }>` — buffered for reconciliation
- `private lastEmitTime: number = 0` — throttle server emissions to ~20Hz
- `private isSolid: ((tileX: number, tileY: number) => boolean) | null` — collision callback

**Constants:**
- `EMIT_INTERVAL_MS = 50` — emit to server every 50ms (20Hz, matches server tick rate)
- `RECONCILIATION_THRESHOLD_PX = 3` — ignore server corrections under this distance (per CONTEXT.md)
- `MAX_PENDING_INPUTS = 30` — cap buffer to prevent memory issues on high latency

**Methods:**

`init(px: number, py: number, zoneId: string)` — set initial position (called on zone load from zone:state).

`setCollisionCallback(isSolid: (tx: number, ty: number) => boolean)` — set the collision lookup. Called by WorldScene when chunk data is available.

`update(dt: number, keys: { W: boolean; A: boolean; S: boolean; D: boolean }, time: number): { px: number; py: number; moved: boolean; direction: Direction | null }` — called every frame from WorldScene.update():
  1. Build KeyState: `{ up: keys.W, down: keys.S, left: keys.A, right: keys.D }`
  2. Compute velocity: `velocityFromKeys(keyState, dt)` (import from `@into-the-void/game-logic`)
  3. If vx === 0 && vy === 0: return current position with moved=false, direction=null
  4. Resolve collision: If `isSolid` is set, call `resolvePixelCollision(this.px, this.py, vx, vy, isSolid)`. Otherwise apply raw velocity.
  5. Update `this.px`, `this.py` to resolved position
  6. Increment `inputSequence`
  7. Build bitmask: `(keys.W ? 1 : 0) | (keys.A ? 2 : 0) | (keys.S ? 4 : 0) | (keys.D ? 8 : 0)`
  8. Push to `pendingInputs`: `{ sequence, keys: bitmask, vx, vy, px: this.px, py: this.py }`
  9. Cap `pendingInputs` at `MAX_PENDING_INPUTS` (shift oldest)
  10. Throttled emit: if `time - lastEmitTime >= EMIT_INTERVAL_MS`, emit `player:pixelMove` via `gameSocket.emit('player:pixelMove', { keys: bitmask, predictedPx: this.px, predictedPy: this.py, sequence: this.inputSequence })` and update `lastEmitTime`
  11. Derive direction from velocity vector for animations:
      - Use `Math.atan2(vy, vx)` mapped to 8 directions
      - Angle ranges: E=(-22.5,22.5], SE=(22.5,67.5], S=(67.5,112.5], SW=(112.5,157.5], W=(157.5,180]∪(-180,-157.5], NW=(-157.5,-112.5], N=(-112.5,-67.5], NE=(-67.5,-22.5]
      - Return the Direction string ('n','ne','e','se','s','sw','w','nw')
  12. Return `{ px: this.px, py: this.py, moved: true, direction }`

`reconcile(serverPx: number, serverPy: number, sequence: number): { px: number; py: number; corrected: boolean }`:
  1. Discard all pendingInputs with sequence <= the server's acknowledged sequence
  2. Start from server position (serverPx, serverPy)
  3. Replay remaining pendingInputs: for each, apply vx/vy to running position (with collision resolution if isSolid is set)
  4. Compute distance between replayed position and current predicted position
  5. If distance < RECONCILIATION_THRESHOLD_PX: return current position with corrected=false (prediction was close enough)
  6. Otherwise: set this.px, this.py to replayed position, return with corrected=true

`getPosition(): { px: number; py: number; zoneId: string }` — return current state.

`reset()` — clear pendingInputs, reset inputSequence to 0. Called on zone transition.

**Imports:**
- `velocityFromKeys`, `resolvePixelCollision`, `KeyState` from `@into-the-void/game-logic`
- `Direction` from `@into-the-void/shared-types`
- `gameSocket` from `../../network/socket`

Do NOT import from the old `MovementController` — this is a complete replacement.

Create `RemotePlayerInterpolator` class that provides smooth rendering of remote players between server position updates.

**Design:** Per-player interpolation buffer. Stores the last 2-3 position snapshots from `positionBatch` events. On each frame, interpolates between the two most recent snapshots based on elapsed time.

**Class state:**
- `private buffers: Map<string, PositionSnapshot[]>` — per-player position buffer keyed by playerId
- Each `PositionSnapshot`: `{ px: number; py: number; timestamp: number }`

**Constants:**
- `BUFFER_SIZE = 3` — keep last 3 snapshots per player
- `SERVER_TICK_MS = 50` — expected interval between server updates (20Hz)
- `INTERPOLATION_DELAY_MS = 100` — render 2 ticks behind to always have data to interpolate between

**Methods:**

`pushPosition(playerId: string, px: number, py: number)`:
  1. Get or create buffer for player
  2. Push `{ px, py, timestamp: Date.now() }` to buffer
  3. If buffer length > BUFFER_SIZE, shift oldest

`getInterpolatedPosition(playerId: string, currentTime: number): { px: number; py: number; moving: boolean; direction: Direction | null } | null`:
  1. Get buffer for player. If no buffer or < 2 entries, return null (not enough data)
  2. Render time = `currentTime - INTERPOLATION_DELAY_MS`
  3. Find the two snapshots that straddle render time: snapshot[i].timestamp <= renderTime < snapshot[i+1].timestamp
  4. If render time is after all snapshots: use last snapshot position (extrapolate=hold), moving=false
  5. If render time is before all snapshots: use first snapshot position, moving=false
  6. Compute interpolation factor: `t = (renderTime - snap[i].timestamp) / (snap[i+1].timestamp - snap[i].timestamp)`, clamp to [0,1]
  7. Interpolate: `px = snap[i].px + (snap[i+1].px - snap[i].px) * t`, same for py
  8. Compute direction from delta (snap[i+1] - snap[i]) using `Math.atan2` → 8-direction snap (same mapping as PixelMovementController)
  9. If delta is essentially zero (< 1px), direction=null, moving=false
  10. Return `{ px, py, moving: moving, direction }`

`removePlayer(playerId: string)` — delete buffer entry (called on player:left).

`clear()` — clear all buffers (called on zone transition).

**Direction helper:** Extract the atan2→Direction mapping to a shared function `velocityToDirection(vx: number, vy: number): Direction | null` at the top of the file, reusable by both classes. Actually — define it in PixelMovementController.ts and export it, then import it in RemotePlayerInterpolator. Or better: define it as a standalone export in a new utility. Since PixelMovementController is in the same directory, put the helper function as an exported function in PixelMovementController.ts:

```typescript
export function velocityToDirection(vx: number, vy: number): Direction | null {
  if (Math.abs(vx) < 0.01 && Math.abs(vy) < 0.01) return null;
  const angle = Math.atan2(vy, vx) * (180 / Math.PI);
  if (angle >= -22.5 && angle < 22.5) return 'e';
  if (angle >= 22.5 && angle < 67.5) return 'se';
  if (angle >= 67.5 && angle < 112.5) return 's';
  if (angle >= 112.5 && angle < 157.5) return 'sw';
  if (angle >= 157.5 || angle < -157.5) return 'w';
  if (angle >= -157.5 && angle < -112.5) return 'nw';
  if (angle >= -112.5 && angle < -67.5) return 'n';
  if (angle >= -67.5 && angle < -22.5) return 'ne';
  return null;
}
```

RemotePlayerInterpolator imports `velocityToDirection` from `./PixelMovementController`.

- `velocityToDirection` from `./PixelMovementController`
