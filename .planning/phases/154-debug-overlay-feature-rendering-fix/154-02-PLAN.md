**Part A: DebugCollisionRenderer**

Create a new class that draws collision boundaries as colored wireframe outlines on the game world when debug mode is active.

```typescript
interface CollisionDataSource {
  getCollisionMap: () => boolean[][] | null;
  getStructures: () => TileStructure[];
  getEntityContainers: () => Map<string, Phaser.GameObjects.Container>;
  tileToScreen: (tileX: number, tileY: number) => { x: number; y: number };
}

export class DebugCollisionRenderer {
  private scene: Phaser.Scene;
  private visible: boolean = false;
  private graphics: Phaser.GameObjects.Graphics | null = null;
  private dataSource: CollisionDataSource;
  private lastDrawTime: number = 0;
  private drawInterval: number = 500; // Redraw every 500ms (collision data doesn't change often)
```

**Color scheme (distinguishable per type):**
- Blocking tiles: `0xff4444` (red), alpha 0.5, lineStyle width 2
- Wall structures: `0xffaa00` (orange/yellow), alpha 0.6, lineStyle width 3
- Feature entity collision boxes: `0x4488ff` (blue), alpha 0.5, lineStyle width 2

**show() method:**
- Set visible = true
- Create graphics object if not yet created (lazy init)
- Set graphics depth very high (999998, just below debug overlay text)
- Immediately draw all collision boundaries

**hide() method:**
- Set visible = false
- Clear and hide graphics (do NOT destroy — reuse)

**update() method — called every frame:**
- If not visible, return immediately
- Throttle redraws to every 500ms
- On redraw, call draw()

**draw() method:**
- Clear graphics
- Draw blocking tiles: iterate collisionMap, for each true cell, draw an isometric diamond outline at that tile position using tileToScreen(). The diamond has 4 points:
  ```
  top:    (screenX, screenY - tileH/2)
  right:  (screenX + tileW/2, screenY)
  bottom: (screenX, screenY + tileH/2)
  left:   (screenX - tileW/2, screenY)
  ```
  Where tileW=256, tileH=128 (ISO_TILE_WIDTH/HEIGHT).

- Draw wall structures: iterate structures array, for each wall-type structure, draw a thicker orange diamond outline at its tile position. Walls are identified by TileStructure entries with type containing 'wall'.

- Draw feature entity collision boxes: iterate entity containers, for each container that has `visibleBounds` data (features), read the container's world position and the visibleBounds, then draw a blue rectangle outline around the feature's collision area. Use the same bounds logic as the hit area calculation.

**Performance note:** Only iterate visible tiles (use camera bounds to cull). For a 64x64 zone, this is at most ~4096 tiles to check but with culling typically ~200-400.

**destroy() method:** Destroy graphics.

**Part B: Fix white outline artifact on feature entities (RENDER-01)**

The white outline artifact on plants/minerals/artifacts is caused by the hoverGlow Graphics object. Investigate two potential causes:

1. **Most likely cause:** The Phaser.GameObjects.Graphics object, even when `setVisible(false)` and `clear()` has been called, may still render a thin white line if the lineStyle was set before hiding. Fix: ensure hoverGlow.clear() is called immediately after creation (before any lineStyle is set), and ensure on pointerout the order is clear() THEN setVisible(false).

2. **Alternative cause:** The sprite texture itself may have white edge pixels from PNG export (premultiplied alpha artifacts). If the outline appears even without hover interaction, the fix is on the sprite loading side — not in EntityRenderer.

**Investigation steps for the executor:**
- Check if the white outline is visible on feature entities even when never hovered (if yes, it's a texture issue, not hoverGlow)
- Check if hoverGlow Graphics has any default draw state after construction

**Fix in EntityRenderer.ts (around line 348-396):**
- After creating hoverGlow, immediately call `hoverGlow.clear()` to ensure no default draw state
- In the pointerout handler, change the order: call `hoverGlow.clear()` first, then `hoverGlow.setVisible(false)` (current code already does this but verify)
- If the issue is that the Graphics object renders even when "empty", consider not adding it to the container until pointerover, and removing it on pointerout. Or set `hoverGlow.setActive(false)` when hidden.

**If the white outline is a texture artifact (not hoverGlow):**
- The fix would be to set `sprite.texture.setFilter(Phaser.Textures.FilterMode.NEAREST)` for feature sprites to avoid bilinear filtering bleed on transparent edges
- OR add a 1px transparent border trim during visible bounds computation

Apply whichever fix resolves the issue. Document the root cause in a code comment.
