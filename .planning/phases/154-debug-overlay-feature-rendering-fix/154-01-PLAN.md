Create a new DebugOverlay class that renders a Minecraft-style F3 debug screen. The overlay is a Phaser system owned by WorldScene.

**Class structure:**
```typescript
export class DebugOverlay {
  private scene: Phaser.Scene;
  private visible: boolean = false;
  private container: Phaser.GameObjects.Container | null = null;
  private bgGraphics: Phaser.GameObjects.Graphics | null = null;
  private textLines: Phaser.GameObjects.Text[] = [];
  private fpsHistory: number[] = [];
  private lastUpdateTime: number = 0;
  private updateInterval: number = 200; // Update text every 200ms to avoid per-frame string allocation
```

**toggle() method:**
- Flips `this.visible`
- If becoming visible: create container + graphics + text objects if not yet created, set visible
- If becoming hidden: set container visible false (do NOT destroy — reuse on next toggle for perf)
- Container should be added to the scene at a very high depth (999999) and set scrollFactor(0) so it stays fixed on screen

**create() method (lazy, called on first toggle-on):**
- Create a container at position (12, 12) — top-left with small margin
- Create a semi-transparent dark background using Graphics: fillStyle(0x000000, 0.65), fillRoundedRect
- Create text lines using monospace font: `{ fontFamily: 'monospace', fontSize: '13px', color: '#00ff00', lineSpacing: 2 }`
- Create ~15 Text objects stacked vertically (one per info line), spaced 18px apart
- Set all text objects' scrollFactor to 0 (fixed to camera)
- Background rect sized to cover all text lines with padding

**update(deltaMs: number) method — called every frame from WorldScene.update():**
- If not visible, return immediately (zero cost when hidden — DEBUG-05)
- Track FPS: push 1000/deltaMs to fpsHistory, keep last 30 samples, compute average
- Throttle text updates to every 200ms (track lastUpdateTime)
- On text update, read state from stores and scene:

**Line layout (3 blocks, separated by blank lines):**

Block 1 — Position & World:
```
Into the Void — Debug (F3)
XY: {px}, {py}
Zone: {currentZoneId}
Tile: {tileX}, {tileY}
Elevation: {elevation}
Tile Type: {tileId} ({tileName})
Biome: {biomeName}
```

Block 2 — Performance:
```
FPS: {avg} ({min}-{max})
Entities: {count}
Ping: {latency}ms
Chunks: {loaded} loaded, {pending} pending, {failed} failed
```

Block 3 — Game State:
```
Day/Night: {phase} ({progress}%)
Combat: {inCombat ? 'ACTIVE' : 'None'}
Target: {targetEntityId ?? 'None'}
```

**Data sources:**
- Player position: `useGameStore.getState().player` — use px, py fields
- Zone ID: `useGameStore.getState().currentZoneId`
- Tile coordinates: Compute from px/py using `Math.floor(px / TILE_SIZE_PX)` and `Math.floor(py / TILE_SIZE_PX)` where TILE_SIZE_PX is imported from game-logic
- Elevation: Read from scene's currentHeights array at tile coords (access via WorldSceneAccessor or pass as callback)
- Tile type: Read from scene's currentTiles array at tile coords
- Biome: `useGameStore.getState()` — use the biome display name from BIOME_DISPLAY_NAMES
- FPS: Computed from delta (self-tracked)
- Entity count: `useEntityStore.getState().entities.size`
- Ping: `useGameStore.getState().latency`
- Chunk counts: Accept a callback/getter from WorldScene that returns {loaded, pending, failed} counts from ChunkManager
- Day/Night phase: Accept DayNightCycle reference, call getCurrentPhase() and getCycleProgress()
- Combat state: `useCombatStore.getState().inCombat` and `.targetEntityId`

**Resize background** after updating text to fit the longest line width + padding.

**destroy() method:** Destroy container and all children.

**Important:** Do NOT import DayNightCycle or ChunkManager directly. Instead, accept getter functions in the constructor or a context object so WorldScene can wire them:

```typescript
  getChunkCounts: () => { loaded: number; pending: number; failed: number };

}
```

  ```typescript

    this.scene.events.emit('input:toggle-debug');
  ```

- Note: F3 should work even when keyboard is disabled for movement (it's a debug toggle, not gameplay input). Add it OUTSIDE the `if (this.scene.input.keyboard?.enabled)` guard — the key listener itself doesn't need the enabled check since it's event-based. But wrap the callback check only if needed. Actually, Phaser key listeners fire regardless of the `enabled` flag on keyboard manager — the `enabled` flag only affects `isDown` polling. So just register the key normally.

```typescript
getChunkStats(): { loaded: number; pending: number; failed: number } {

}
```
