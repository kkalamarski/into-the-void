<task type="auto">
  <name>Task 1: Add entity layer offset to depth calculation</name>
  <files>apps/web/src/game/utils/IsometricTransform.ts</files>
  <action>
Add an entity layer offset to the depth calculation to ensure entities always render above terrain at the same position.

Current formula: `screen.y + (gridX * 0.0001) + (elevation * 0.1) + priorityBoost`

The problem is the elevation weight (0.1) is tiny compared to screen.y changes. When an entity moves, its Y position changes by ~64px (half tile height), but elevation only adds 0.1 per level. This causes depth values to fluctuate incorrectly.

**Fix approach:**

1. Add constant `ENTITY_LAYER_OFFSET = 1000` at top of file. This offset is large enough to guarantee all entities at any position render above all terrain tiles at the same or lower Y position, but small enough to not interfere with proper front-to-back sorting between entities.

2. Modify `calculateDepth` signature to accept optional `isEntity: boolean = false` parameter:
   ```typescript
   calculateDepth(gridX: number, gridY: number, elevation: number = 0, priorityBoost: number = 0, isEntity: boolean = false): number
   ```

3. In the return statement, add `(isEntity ? ENTITY_LAYER_OFFSET : 0)` to the calculation:
   ```typescript
   return screen.y + (gridX * 0.0001) + (elevation * this.elevationWeight) + priorityBoost + (isEntity ? ENTITY_LAYER_OFFSET : 0);
   ```

This ensures:
- All tiles get depth values in range [0, ~10000] (based on typical world size)
- All entities get depth values in range [1000, ~11000]
- Entities at the same screen Y as a tile will have depth 1000+ higher, rendering in front
- Front-to-back sorting between entities still works correctly via screen.y
  </action>

Run `npx tsc --noEmit -p apps/web/tsconfig.json` to verify TypeScript compiles without errors.
  </verify>
  <done>
IsometricTransform.calculateDepth accepts isEntity parameter and adds ENTITY_LAYER_OFFSET (1000) when true.
  </done>
