  <name>Task 1: Add custom hitArea rectangles to entity sprites and click priority</name>
  <files>apps/web/src/game/rendering/EntityRenderer.ts</files>
  <action>
  Replace the default `setInteractive()` call with a custom `hitArea` rectangle that covers only the visible art portion of each sprite, excluding transparent padding.

  **In `createEntityContainer`, after the sprite is created and scaled, replace:**
  ```typescript
  sprite.setInteractive({ useHandCursor: isClickable });
  ```

  **With a per-type hitArea calculation:**

  For entities with `setOrigin(0.5, 1.0)` (bottom-center origin), the sprite's local coordinate system has (0,0) at the top-left of the full texture. The origin point at (0.5, 1.0) means the bottom-center of the texture is at the container position. We need a hitArea in the sprite's LOCAL unscaled coordinate space.

  ```typescript
  if (isClickable) {
    // Calculate tight hitArea in sprite's local coordinate space (unscaled).
    // For bottom-center origin (0.5, 1.0), the sprite's (0,0) is top-left of texture.
    // The visible art is assumed to be the center ~70% width and bottom ~80% height
    // (top portion is typically transparent headroom / padding).
    const texW = sprite.width;
    const texH = sprite.height;

    // Tight rect: horizontal center 70% width, bottom 80% of height
    const hitPadX = texW * 0.15; // 15% padding each side
    const hitPadTop = texH * 0.2; // 20% padding top (transparent headroom)
    const hitRect = new Phaser.Geom.Rectangle(
      hitPadX,
      hitPadTop,
      texW - hitPadX * 2,
      texH - hitPadTop
    );
    sprite.setInteractive(hitRect, Phaser.Geom.Rectangle.Contains);
    sprite.input!.cursor = 'pointer';
  } else {
    sprite.setInteractive();
  }
  ```

  **Add specific overrides for animated creatures** that have known tight sprite sheets (48-128px sprites often have less padding). For animated creatures, use a tighter hitArea — center 80% width, bottom 85% height:
  ```typescript
  const isAnimated = this.isCreature(entity) && entity.speciesId && EntityRenderer.ANIMATED_CREATURES.has(entity.speciesId);
  if (isAnimated) {
    hitPadX = texW * 0.10;
    hitPadTop = texH * 0.15;
  }
  ```
  Apply this before creating `hitRect`.

  **Click priority — creatures over resources:**
  Phaser's input priority is set via `sprite.setInteractive({ ... }).setDepth()` but more directly via input priority. After calling `setInteractive`, set input priority for creatures higher than plants/minerals:
  ```typescript
  if (entity.type === 'creature') {
    sprite.input!.priorityID = 2; // Creatures get highest click priority
  } else {
    sprite.input!.priorityID = 1; // Plants, minerals get lower priority
  }
  ```
  This ensures that when sprites overlap, clicking selects the creature first per CONTEXT.md: "Click priority: creatures first, then resources."

  Add a hover indicator (outline glow) that appears when the cursor hovers over any clickable entity. Per CONTEXT.md: "Hover indicator: outline glow around the entity when cursor is over a clickable entity."

  **1. Add hover glow graphics in EntityRenderer.createEntityContainer:**

  After the sprite is made interactive (inside the `isClickable` branch), add pointerover/pointerout handlers that draw/clear a glow outline around the sprite:

  ```typescript
  if (isClickable) {
    // Create a graphics object for hover glow (initially invisible)
    const hoverGlow = this.scene.add.graphics();
    hoverGlow.setVisible(false);
    container.add(hoverGlow);
    container.setData('hoverGlow', hoverGlow);

    sprite.on('pointerover', () => {
      // Draw glow outline around the sprite's visible bounds
      hoverGlow.clear();
      // Use actual sprite screen bounds relative to container
      const halfW = (sprite.width * sprite.scaleX) / 2;
      const h = sprite.height * sprite.scaleY;
      const yOff = spriteYOffset; // sprite's Y position in container
      hoverGlow.lineStyle(3, 0xffffff, 0.6);
      hoverGlow.strokeRoundedRect(-halfW, yOff - h, halfW * 2, h, 4);
      hoverGlow.setVisible(true);
    });

    sprite.on('pointerout', () => {
      hoverGlow.setVisible(false);
      hoverGlow.clear();
    });
  }
  ```

  IMPORTANT: The existing pointerover/pointerout handlers for plants/minerals (showing nameplates and yield bars) must be preserved. The hover glow is ADDITIVE — it does not replace the nameplate show/hide. Structure the code so that for plants/minerals, pointerover triggers BOTH the nameplate visibility AND the hover glow. The easiest approach: add the hover glow handlers for ALL clickable entities, then keep the existing plant/mineral nameplate handlers separately (they already exist in the code).

  **2. Make hover glow consistent with existing selection highlighting:**
  Per CONTEXT.md: "The hover outline glow should be consistent with any existing selection highlighting in the game." The existing `TargetHighlight` uses an elliptical ring at the entity's ground position. The hover glow should use a similar white outline but more subtle (thinner, lower alpha) to differentiate from the combat selection ring.

  Use `0xffffff` (white) at alpha `0.6` with line width `3`. This is visually distinct from the `TargetHighlight` which uses color-coded rings (green/yellow/orange/red by behavior) with alpha pulsing between 0.4-0.8 and line width 4.

  **3. Clean up hover glow on entity removal:**
  In any entity cleanup/destroy path in WorldScene, the container destruction will automatically clean up child graphics objects, so no explicit cleanup is needed. However, ensure the hover glow doesn't persist when the entity is destroyed — since it's a child of the container, `container.destroy()` handles this.
