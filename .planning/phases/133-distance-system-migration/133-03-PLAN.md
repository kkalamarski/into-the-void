The direction calculation works correctly with tile coords because it only cares about which way to step, not about exact distance. **Do NOT change the flee/moveToward step logic** — only change the DETECTION distance (which is already handled by the `nearbyPlayers` filter above).

**Important:** The `flee` function's direction computation (`creature.position.x - player.position.x`) should ideally use player pixel position for more accurate direction. Convert to pixel coords for direction only:
```typescript
function flee(creature: Creature, player: PlayerPublic, collisionMap: boolean[][]): AiTickResult {
  const { px: cpx, py: cpy } = tileToPixelCenter(creature.position.x, creature.position.y);
  const rawDx = cpx - player.px;
  const rawDy = cpy - player.py;
  const dx = rawDx === 0 ? 0 : rawDx > 0 ? 1 : -1;
  const dy = rawDy === 0 ? 0 : rawDy > 0 ? 1 : -1;
  // ... rest of function stays the same (tile-step movement)
}
```
Similarly update `moveToward` when chasing a player target — use pixel coords for direction:
```typescript
function moveToward(
  creature: Creature,
  target: { x: number; y: number } | PlayerPublic,
  collisionMap: boolean[][],
  isReturning: boolean,
): AiTickResult {
  const { px: cpx, py: cpy } = tileToPixelCenter(creature.position.x, creature.position.y);
  let targetPx: number, targetPy: number;
  if ('px' in target && 'py' in target) {
    targetPx = target.px;
    targetPy = target.py;
  } else {
    const tc = tileToPixelCenter(target.x, target.y);
    targetPx = tc.px;
    targetPy = tc.py;
  }
  const rawDx = targetPx - cpx;
  const rawDy = targetPy - cpy;
  // ... rest unchanged (tile-step movement with ±1 dx/dy)
}
```
This makes chase/flee direction more accurate when the player is between tiles, but the creature still moves one tile per tick.
