Create a new file `apps/game-server/src/game/movement.service.ts` implementing the full pixel movement tick loop.

**Structure:**
```typescript
import { Injectable, OnModuleInit } from '@nestjs/common';
import { Server } from 'socket.io';
import { PlayerService } from './player.service';
import { ZonesService } from '../zones/zones.service';
import {
  bitmaskToKeyState,
  velocityFromKeys,
  resolvePixelCollision,
  validatePixelSpeed,
} from '@into-the-void/game-logic';

interface PixelMoveInput {
  keys: number;
  predictedPx: number;
  predictedPy: number;
  sequence: number;
}
```

**Constants (Claude's Discretion decisions):**
- `TICK_MS = 50` — 20Hz tick rate
- `BROADCAST_RADIUS_PX = 1536` — 12 tiles (covers aggro + leash range with margin)
- `MAX_DT = 0.2` — cap delta-time at 200ms to prevent teleport on stale input

**Key fields:**
- `private pendingInputs: Map<string, PixelMoveInput>` — latest input per player (keyed by playerId)
- `private server: Server | null = null` — set via `setServer()` method
- `private tickTimer: ReturnType<typeof setInterval> | null = null`

**Methods:**

1. `setServer(server: Server): void` — stores Socket.IO server reference (called from GameGateway.afterInit, same pattern as PlayerService)

2. `queueInput(playerId: string, input: PixelMoveInput): void` — stores only the latest input, overwriting any previous unprocessed input for that player

3. `onModuleInit(): void` — starts the tick loop: `this.tickTimer = setInterval(() => this.tick(), TICK_MS);`

4. `private tick(): void` — the core loop:
   a. Drain `pendingInputs` into a local array and clear the map
   b. For each pending input:
      - Get player via `playerService.getPlayerById(playerId)`
      - Skip if player is null, dead (`player.isDead`), or has no position
      - Compute `dt = Math.min((Date.now() - player.lastPxInputTime) / 1000, MAX_DT)`
      - Update `player.lastPxInputTime = Date.now()`
      - Convert bitmask: `const keyState = bitmaskToKeyState(input.keys)`
      - Compute velocity: `const { vx, vy } = velocityFromKeys(keyState, dt)` (speedMultiplier defaults to 1.0 for Phase 132 — per research recommendation)
      - **Speed validation:** Call `validatePixelSpeed(player.px, player.py, input.predictedPx, input.predictedPy, dt)`. If false:
        - Emit `positionCorrection` to `player.socketId`: `{ px: player.px, py: player.py, sequence: input.sequence }`
        - Continue to next player (do NOT update position)
      - **Collision resolution:** Get chunk via `zonesService.getChunkSync(player.position.zoneId)`. If chunk is undefined (zone not cached), skip this player this tick (no-op).
        - Build `isSolid` callback: `(tx, ty) => chunk.collisions[ty]?.[tx] ?? true` (default true for out-of-bounds = solid wall)
        - Call `resolvePixelCollision(player.px, player.py, vx, vy, isSolid)`
      - Update player: `player.px = resolved.px; player.py = resolved.py`
      - Add to dirty list: `{ playerId, px: resolved.px, py: resolved.py }`
   c. If dirty list is empty, return
   d. Call `broadcastBatch(dirty)`

5. `private broadcastBatch(dirty: Array<{ playerId: string; px: number; py: number }>): void`:
   - Group dirty players by `player.position.zoneId`
   - For each zone:
     - Get all online players in that zone via `playerService.getPlayersInZone(zoneId)` — but we need the ConnectedPlayer (with px/py), not PlayerPublic. Instead, iterate `playerService.getAllOnlinePlayers()` filtered to this zone.
     - For each observer in the zone:
       - Filter dirty movers to only those within `BROADCAST_RADIUS_PX` of the observer (using `Math.hypot(m.px - observer.px, m.py - observer.py)`)
       - Exclude self: skip entries where `m.playerId === observer.id`
       - If any nearby movers, emit `positionBatch` to `observer.socketId`: `{ updates: nearby.map(m => ({ playerId: m.playerId, px: m.px, py: m.py })) }`
   - IMPORTANT: Use `this.server?.to(observer.socketId).emit(...)` for individual socket targeting

**NestJS pattern:** Inject `PlayerService` and `ZonesService` via constructor. Use `@Injectable()` decorator. Implement `OnModuleInit`.

**Important edge case:** When `vx === 0 && vy === 0` (no keys pressed), still mark player as having processed input (update lastPxInputTime) but do NOT add to dirty list (player didn't move).

**Important:** Do NOT include any server-side handling of zone transitions in this plan. Zone transitions remain tile-based via the old `player:move` handler until Phase 134. This tick loop only handles within-zone movement.
