# Plan 159-02: Fix Creature AI Movement and Client Rendering

## Objective

Ensure creatures visibly move on screen (wander, flee, chase) and that creature position updates are received and rendered by the client in real time.

## Context

The user reports creatures are alive but don't react to the player — distance calculations return wrong values so aggro never triggers, and wander movement may be happening but not visible.

### Analysis

1. **Creature AI tick runs server-side** in `ai.service.ts` (`runZoneTick`). It calls `tickCreatureAI` which dispatches to behavior strategies.

2. **Distance calculations** use `creatureToPlayerDist()` in `creature-ai-helpers.ts`:
   ```typescript
   const { px: cpx, py: cpy } = tileToPixelCenter(creature.position.x, creature.position.y);
   return pixelDistanceTo(cpx, cpy, player.px, player.py);
   ```
   This converts creature tile coords to pixel center, then compares to player px/py. Since creatures are tile-snapped and player is pixel-based, both should be in zone-local pixel space. If this is correct, distances should work.

3. **Creature position updates** are broadcast via `entity:batch` events. The client handles these in `entityStore.ts` (updates entity data) and `gameStore.ts` (forwards to WorldScene for visual rendering).

4. **Visual rendering** in `EntityManager.updateEntity()` calls `positionToWorldCoords(changes.position)` then `isoTransform.gridToScreen()` to position the creature sprite.

### Potential Issues

- **Aggro radius too small**: `AGGRO_RADIUS_PX = 512px` (4 tiles). If distance calc is wrong by even a few tiles, aggro never triggers.
- **Collision map blocks all moves**: If `collisionMap[ny][nx]` is true for all adjacent tiles, creatures can't move at all.
- **Entity:batch not reaching client**: Socket room membership issue — player not in the zone room when entity:batch fires.
- **Creature AI tick not starting**: `activateZone()` may not be called, or hub zone check may incorrectly skip world zones.

<task id="3">
**Fix creature-to-player distance calculations if broken**

If distances are wrong (e.g., thousands of pixels when standing next to a creature), the issue is coordinate space mismatch. Fix by ensuring both creature and player positions use the same coordinate space.

Possible fix — creatures store tile positions which are zone-local. `tileToPixelCenter` converts correctly. If player.px/py are somehow world-absolute, convert them to zone-local before comparison:
```typescript
// If player px/py includes world offset, subtract it
const zoneOffsetPx = zoneCoords.x * ZONE_SIZE * TILE_SIZE_PX;
const localPx = player.px - zoneOffsetPx;
```

OR: If player px/py are already zone-local (which they should be based on init code), the distance calc is correct and the issue is elsewhere.

Apply fix based on runtime findings from task 2.
</task>
