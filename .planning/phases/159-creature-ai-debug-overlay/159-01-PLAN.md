# Plan 159-01: Fix Coordinate Pipeline

## Objective

Fix the debug overlay showing wrong tile type and elevation, and ensure the player's px/py correctly maps to the tile grid for ALL downstream consumers (elevation lookup, distance calculations, ability range checks).

## Context

The user reports: (1) debug overlay shows wrong tile type/elevation, (2) player sinks (wrong elevation lookup), (3) "out of range" errors when standing next to creatures. All symptoms point to the player's pixel position mapping to the wrong tile somewhere in the pipeline.

### Root Cause Investigation

After code review, the `resolvePixelCollision` function in `pixel-validation.ts` does NOT leak elevation-offset coordinates — it correctly returns original coords + velocity. The elevation offset is only used inside `hitsWall()` for collision lookups.

However, the debug overlay in `DebugOverlay.ts` (pushData method, lines 66-72) does:
```
tileX = Math.floor(px / TILE_SIZE_PX)
tileY = Math.floor(py / TILE_SIZE_PX)
elevation = this.dataSource.getElevation(tileX, tileY)
tileType = this.dataSource.getTileType(tileX, tileY)
```

The `getElevation` and `getTileType` callbacks in WorldScene (lines 160-161) use `this.currentHeights?.[ty]?.[tx]` and `this.currentTiles?.[ty]?.[tx]` — zone-local arrays. The player's px/py SHOULD be zone-local, so `Math.floor(px / 128)` should yield valid zone-local tile indices.

**Possible issues to investigate at runtime:**
1. After zone transition, `currentTiles`/`currentHeights` may not be updated before the debug overlay reads them (stale data from previous zone)
2. The player px/py may not be reset properly on zone transition, leaving world-absolute coords that don't match the zone-local array
3. The `getHeight` callback passed to collision resolution uses world-offset coordinates (`offsetX + tx`), but the debug overlay uses raw zone-local coords — if these resolve to different elevation values, the player walks on one elevation while the debug shows another

Based on the runtime investigation, fix the coordinate mismatch. The most likely scenarios and fixes:

**Scenario A: px/py are world-absolute but array is zone-local**
- In DebugOverlay.ts `pushData()`, subtract the zone offset before tile lookup:
  ```typescript
  const zoneOffset = this.dataSource.getZoneOffset?.() ?? { x: 0, y: 0 };
  const tileX = Math.floor(px / TILE_SIZE_PX) - zoneOffset.x;
  const tileY = Math.floor(py / TILE_SIZE_PX) - zoneOffset.y;
  ```
- OR: change the getElevation/getTileType callbacks to use world-aware lookups via `getWorldTileHeight`/`resolveWorldToChunkLocal`

**Scenario B: Stale array data after zone transition**
- Ensure `currentHeights`/`currentTiles` are updated BEFORE the debug overlay reads them
- Check ordering in `commitZoneTransition()` and `loadZoneFromState()`

**Scenario C: Hub zone vs open-world zone coordinate mismatch**
- Hub zones use local coords directly; open-world zones use world offset
- The debug overlay may need to distinguish between these

Apply the appropriate fix based on findings.
</task>

<task id="4">
**Update debug overlay to use world-aware tile lookups**

Regardless of root cause, harden the debug overlay by changing `getElevation` and `getTileType` callbacks to use the cross-chunk-aware world lookup methods instead of raw array access:

In `apps/web/src/game/scenes/WorldScene.ts`, update the debug data source:
```typescript
getElevation: (tx, ty) => {
  const zoneCoords = this.parseZoneCoords(this.currentZoneId);
  const currentSize = getZoneSize(this.currentZoneId);
  if (isHubZone(this.currentZoneId)) {
    return this.currentHeights?.[ty]?.[tx] ?? 0;
  }
  const worldX = zoneCoords.x * currentSize + tx;
  const worldY = zoneCoords.y * currentSize + ty;
  return this.getWorldTileHeight(worldX, worldY);
},
getTileType: (tx, ty) => {
  if (isHubZone(this.currentZoneId)) {
    return this.currentTiles?.[ty]?.[tx] ?? 0;
  }
  const r = this.resolveWorldToChunkLocal(
    this.parseZoneCoords(this.currentZoneId).x * getZoneSize(this.currentZoneId) + tx,
    this.parseZoneCoords(this.currentZoneId).y * getZoneSize(this.currentZoneId) + ty
  );
  return r?.chunk?.tiles?.[r.localY]?.[r.localX] ?? 0;
}
```

This ensures the debug overlay always gets the correct tile data regardless of coordinate space issues.
</task>
