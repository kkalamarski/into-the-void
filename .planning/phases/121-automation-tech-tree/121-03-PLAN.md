```typescript
@Injectable()
export class AutomationService implements OnModuleInit {
```

**Internal state:**
```typescript
interface DeployableState {
  id: string;
  deployableType: AutomationStructureType;
  name: string;
  ownerId: string;
  position: { x: number; y: number; zoneId: string };
  durability: number;
  maxDurability: number;
  fuelRemaining: number;
  maxFuel: number;
  accumulatedResources: { itemId: string; quantity: number }[];
  status: 'active' | 'depleted' | 'husk';
  deployedAt: number;
  expiresAt: number | null;
  lastTickAt: number;
  // Refinery-specific
  activeRecipe?: { recipeId: string; startedAt: number; inputConsumed: boolean };
  dirty: boolean; // Track if state changed since last flush
}
```

- `private deployables: Map<string, DeployableState> = new Map();`
- `private tickInterval: ReturnType<typeof setInterval> | null = null;`
- `private flushInterval: ReturnType<typeof setInterval> | null = null;`
- `private server: Server | null = null;`

**Constructor dependencies:**
- DatabaseService, PlayerService, InventoryService, ZonesService, EventEmitter2

**Lifecycle:**

1. `onModuleInit()` — call `loadActiveDeployables()` to load all active/depleted deployables from DB into memory map. Start tick interval at 60,000ms. Start flush interval at 300,000ms (5 min).

2. `setServer(server: Server)` — store Socket.IO server ref (called from GameGateway.afterInit)

3. `async loadActiveDeployables()` — call `getAllActiveDeployables(db)`, convert each DB row to DeployableState, populate this.deployables Map. Log count loaded.

**Tick processing (60s interval):**

4. `private processTick(): void` — iterate all deployables in Map:
   - Skip if status !== 'active'
   - Skip if fuelRemaining <= 0 (transition to 'depleted', mark dirty)
   - Check expiry: if expiresAt && Date.now() > expiresAt, set status to 'husk', mark dirty, continue
   - Apply degradation: if config.degradationPerDay > 0, calculate per-tick degradation (config.degradationPerDay / (24 * 60) per tick), subtract from durability. If durability <= 0, set status 'husk', mark dirty, continue
   - Consume fuel: fuelRemaining -= config.fuelPerTick
   - If deployableType !== 'refinery': accumulate resources. Look up what resource the node produces (stored in properties.resourceItemId). Add { itemId, quantity: config.outputPerTick } to accumulatedResources (merge with existing if same itemId).
   - If deployableType === 'refinery': process recipe. If activeRecipe exists, check if Date.now() - activeRecipe.startedAt >= recipe.durationMs. If complete, add output to accumulatedResources, clear activeRecipe. If no activeRecipe, check if enough input resources in accumulated to start one.
   - Mark dirty = true
   - Update lastTickAt = Date.now()

   CRITICAL: This method MUST be synchronous. No async calls. All data from in-memory Map.

5. `private async flushToDB(): Promise<void>` — iterate all deployables where dirty === true, batch update to DB using updateDeployableAccumulated(). Reset dirty flag. Log flush count.

**Deploy handler:**

6. `async handleDeploy(playerId: string, deployableItemId: string, position: Position): Promise<{success, error?, deployable?}>` —
   - Validate player level >= config.requiredLevel
   - Check player limit: count existing deployables of this type for player. If >= config.maxPerPlayer, return error.
   - If config.nodeRequired: verify position has a mineral/plant entity (resource node). Get the resource node's resourceId/speciesId for properties.resourceItemId.
   - Consume the deployable item from player inventory (InventoryService.removeItem)
   - Create DB record via createDeployable()
   - Create DeployableState in Map with status 'active', fuelRemaining 0 (starts empty — player must refuel)
   - Spawn DeployableEntity in zone via ZonesService.spawnEntity()
   - Emit 'automation:deployed' to player
   - Return success with deployable info

**Collect handler:**

7. `async handleCollect(playerId: string, deployableId: string): Promise<{success, error?, items?}>` —
   - Get state from Map. If not found, return error.
   - NOTE: ANY player can collect (PvP looting per CONTEXT.md). No owner check.
   - Clone accumulatedResources, clear them on state, mark dirty
   - Add each collected item to player inventory via InventoryService.addItem()
   - Emit 'automation:collected' to player
   - Return collected items

**Refuel handler:**

8. `async handleRefuel(playerId: string, deployableId: string, fuelInstanceId: string): Promise<{success, error?}>` —
   - Get state from Map. If not found, return error.
   - Only OWNER can refuel (check ownerId === playerId)
   - Get fuel item from player inventory. Verify it matches config.fuelItemId.
   - Remove fuel item from inventory
   - Add config.fuelPerItem to fuelRemaining (cap at maxFuel)
   - If status was 'depleted', change to 'active'
   - Mark dirty
   - Emit 'automation:refueled' to player

**Dismantle handler:**

9. `async handleDismantle(playerId: string, deployableId: string): Promise<{success, error?, recoveredItems?}>` —
   - Get state from Map. Only OWNER can dismantle.
   - Calculate recovered materials (50% of deployable item value as common reagents)
   - Add recovered items to player inventory
   - Remove from Map, delete from DB, despawn zone entity
   - Emit 'automation:dismantled' to player

**Interact handler (loot window):**

10. `async handleInteract(playerId: string, entityId: string): Promise<LootWindowData | null>` —
    - Find deployable in Map by matching entity ID pattern or searching by position
    - Build LootWindowData with isOwner check
    - Emit 'automation:loot_window' to player

**Panel handler:**

11. `async handlePanelRequest(playerId: string): Promise<AutomationPanelEntry[]>` —
    - Filter Map entries where ownerId === playerId
    - Map to AutomationPanelEntry format
    - Emit 'automation:panel_state' to player

**Cleanup:**

12. `onPlayerDisconnect(playerId: string)` — no cleanup needed (deployables persist)
13. `onModuleDestroy()` — flush all dirty state to DB, clear intervals

**Register in game.module.ts:**
- Import AutomationService
- Add to providers and exports arrays (same position pattern as HazardService)

**Add 6 @SubscribeMessage handlers:**

1. `@SubscribeMessage('automation:deploy')`
```typescript
async handleAutomationDeploy(
  @ConnectedSocket() client: Socket,
  @MessageBody() data: ClientEvents['automation:deploy']
) {
  const player = this.playerService.getPlayerBySocket(client.id);
  if (!player) return;
  const result = await this.automationService.handleDeploy(player.id, data.deployableItemId, data.position);
  if (!result.success) {
    client.emit('error', { code: 'AUTOMATION_DEPLOY_FAILED', message: result.error });
    return;
  }
  // Emit inventory update to player
  const inventory = this.inventoryService.getInventory(player.id);
  if (inventory) client.emit('inventory:update', inventory);
  // Broadcast entity spawn to zone
  if (result.deployable) {
    this.server.to(player.position.zoneId).emit('entity:spawn', result.deployable);
  }
}
```

2. `@SubscribeMessage('automation:interact')` — get loot window data, emit 'automation:loot_window' to client

3. `@SubscribeMessage('automation:collect')` — collect accumulated resources, emit 'automation:collected' + 'inventory:update' to client

4. `@SubscribeMessage('automation:refuel')` — refuel structure, emit 'automation:refueled' + 'inventory:update' to client

5. `@SubscribeMessage('automation:dismantle')` — dismantle structure, emit 'automation:dismantled' + 'inventory:update' to client, broadcast 'entity:despawn' to zone

6. `@SubscribeMessage('automation:panel_request')` — get panel state, emit 'automation:panel_state' to client

For each handler: validate player exists via getPlayerBySocket(), delegate to AutomationService method, handle errors via client.emit('error', ...), emit inventory:update after any inventory change.
