# Plan 155-01: Centralize elevation constant and update rendering to 64px step

## Objective

Create a single shared constant file for ELEVATION_HEIGHT_STEP (64px) and WALL_RENDER_HEIGHT (256px), then update all rendering files to import from it. Change SH (side height) in procedural tile generation to 64px so terrain cubes render as slabs. Wall tiles must render at 4x height (256px) to tower visibly.

## must_haves

- ELEVATION_HEIGHT_STEP is 64 (not 128) everywhere in the codebase
- Terrain tiles visually render as thin slabs (64px side height)
- Wall tiles render at 256px height (4x the 64px step), towering above ground
- No duplicate definitions of ELEVATION_HEIGHT_STEP remain — single source of truth
- SH constant in ProceduralTileGenerator and AbstractTileRenderStrategy is 64
- ViewportCuller MAX_STRUCTURE_HEIGHT recalculated with 64px step

## Tasks

<task id="1">
Create shared elevation constants file

Create `apps/web/src/game/constants/elevation.ts`:
```typescript
/** Pixels per elevation level — terrain tiles render as thin slabs */
export const ELEVATION_HEIGHT_STEP = 64;

/** Wall tiles render at 4x elevation step to tower over ground */
export const WALL_RENDER_HEIGHT = 256;

/** Maximum elevation level in the world */
export const MAX_ELEVATION = 5;
```

This becomes the single source of truth. All other files import from here.
</task>

<task id="2" depends_on="1">
Update TileRenderer.ts

1. Remove the local `const ELEVATION_HEIGHT_STEP = 128;` declaration (line 6)
2. Add import: `import { ELEVATION_HEIGHT_STEP } from '../constants/elevation';`
3. All existing uses of ELEVATION_HEIGHT_STEP in this file already reference the local const, so the import swap is sufficient
4. The stacking logic at line 221 (`const yOffset = (elevation - level) * ELEVATION_HEIGHT_STEP`) will automatically use 64px
5. Verify the `drawElevationEdge` method still works — it draws edge highlights based on elevation differences, not absolute pixel values, so it should be fine
</task>

<task id="3" depends_on="1">
Update ProceduralTileGenerator.ts — change SH to 64px for slab rendering

1. Change line 22: `const SH = 128;` → `const SH = 64;`
2. Update the comment: `// side height — thin slab (matches ELEVATION_HEIGHT_STEP for seamless stacking)`
3. This changes the south face and east face geometry of baked tile textures:
   - South face becomes: (0,64) → (128,128) → (128,192) → (0,128) (shorter by 64px)
   - East face becomes: (128,128) → (256,64) → (256,128) → (128,192) (shorter by 64px)
4. The canvas size for baked textures may need adjustment — currently 256x256. With SH=64, total height is HH*2 + SH = 128 + 64 = 192. Canvas can stay 256x256 (extra space is transparent) OR reduce to 256x192 for efficiency.
5. IMPORTANT: Check all `fillTriangle` / `fillPath` calls in strategy files that reference the south/east face vertices using SH. The abstract base and concrete strategies use the exported SH from AbstractTileRenderStrategy, so update that first (task 4).

**Wall tile handling**: Tiles with `isBlocking=true` (walls) need special treatment. When baking wall tile textures, SH should be WALL_RENDER_HEIGHT (256) instead of 64. Check if ProceduralTileGenerator can detect wall tiles via TileRegistry and use the larger SH for those. If the strategy pattern already handles this (wall strategies), modify the wall strategies to use a larger SH.

Look at how `bakeTile` works — it calls strategy.render(). If strategies draw their own side faces, each wall strategy needs its SH overridden. If `bakeTile` draws side faces generically, add a branch: `const sideHeight = isWallTile ? WALL_RENDER_HEIGHT : SH;`
</task>

<task id="4" depends_on="1">

3. All concrete tile strategies import SH from this file — they will automatically get the new value
4. For wall tile strategies (if any exist that draw taller side faces), they may need a separate `WALL_SH = 256` or import WALL_RENDER_HEIGHT from constants

Check `apps/web/src/game/rendering/tile-strategies/` for any wall-specific strategy files that might need the taller height.
</task>

<task id="6" depends_on="1">
Update ViewportCuller.ts

1. Remove local `const MAX_ELEVATION = 5;` and `const ELEVATION_HEIGHT_STEP = 128;`
2. Add import: `import { ELEVATION_HEIGHT_STEP, MAX_ELEVATION } from '../constants/elevation';`
3. MAX_STRUCTURE_HEIGHT will now be `5 * 64 = 320` — but wait, original was `5 * 128 = 640` (the comment said 160 which was wrong). With 64px step it becomes 320px. This controls viewport cull padding, so structures up to 320px tall need to be visible. Since wall height is 256px, this is sufficient.
4. Keep the derived constant: `const MAX_STRUCTURE_HEIGHT = MAX_ELEVATION * ELEVATION_HEIGHT_STEP;`
</task>
