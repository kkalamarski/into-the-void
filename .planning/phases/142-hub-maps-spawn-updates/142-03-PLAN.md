<task id="1">
<title>Audit and fix portal interaction for 128x128 maps</title>
<details>
The portal:use handler in game.gateway.ts checks `zoneState.chunk.tiles[player.position.y]?.[player.position.x]` to verify the player is on a portal tile. This works with tile-integer positions.

**Check these integration points:**

1. **Hub exit (portal in hub):** When a player is in a hub and uses portal:use, the code checks `isHubZone()` first and calls `handleHubLeave()`. This path does NOT check if the player is standing on a portal tile — it just teleports them out. This is fine for now, but verify the flow works.

2. **Hub entry (portal in world to hub):** When a player in a world zone stands on a portal and uses portal:use, the code teleports them to their faction hub using `getFactionRespawnPosition()`. After Plan 02 fixes, this should use the correct coordinates.

3. **Pixel position to tile conversion:** The portal check uses `player.position.y` and `player.position.x`. With pixel movement (v1.27), player positions are in pixel coordinates. Check if there is a pixel-to-tile conversion before the portal tile check. If the portal check is using raw pixel positions as tile indices, it will always fail because pixel coordinates are much larger than tile indices.

**Search for the tile lookup code:**
```bash
grep -n "tiles\[.*position" apps/game-server/src/game/game.gateway.ts
```

If the portal check is already correctly converting pixel to tile coordinates, no change needed. If it uses raw pixel positions, add the conversion:
```typescript
import { pixelToTile } from '@into-the-void/game-logic';
// or calculate: Math.floor(player.position.x / TILE_SIZE), Math.floor(player.position.y / TILE_SIZE)
```

4. **Verify hub leave teleports to correct world zone** — the handleHubLeave should place the player in a valid world zone. Check this still works.
</details>
</task>
