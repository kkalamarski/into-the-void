Create `apps/web/src/store/moderationStore.ts` as a Zustand store:

**State shape:**
```typescript
interface ModerationState {
  mutedIds: Set<string>;       // Set of muted character IDs (for O(1) lookup)
  blockedIds: Set<string>;     // Set of blocked character IDs
  loaded: boolean;             // Whether initial load from REST API is complete

  // Actions
  loadModeration: () => Promise<void>;  // Fetch mutes + blocks from REST API
  addMute: (targetCharacterId: string) => Promise<void>;
  removeMute: (targetCharacterId: string) => Promise<void>;
  addBlock: (targetCharacterId: string) => Promise<void>;
  removeBlock: (targetCharacterId: string) => Promise<void>;
  isMuted: (characterId: string) => boolean;
  isBlocked: (characterId: string) => boolean;
  reset: () => void;
}
```

**Implementation details:**

1. `loadModeration`: Get characterId from `useGameStore.getState().player?.id`. If no player, return early. Call `apiCall<PlayerMute[]>(`/moderation/mutes/${characterId}`)` and `apiCall<PlayerBlock[]>(`/moderation/blocks/${characterId}`)` in parallel with `Promise.all`. Extract `mutedCharacterId` / `blockedCharacterId` into Sets. Set `loaded: true`. Wrap in try/catch — log error but don't crash (graceful degradation).

2. `addMute(targetCharacterId)`: Get characterId from gameStore player. Call `apiCall('/moderation/mutes', { method: 'POST', body: JSON.stringify({ characterId, targetCharacterId }) })`. On success, add targetCharacterId to mutedIds set (optimistic update is fine here since the REST call is fast, but do it after the API call to ensure persistence).

3. `removeMute(targetCharacterId)`: Get characterId. Call `apiCall(`/moderation/mutes/${characterId}/${targetCharacterId}`, { method: 'DELETE' })`. Remove from mutedIds set.

4. `addBlock(targetCharacterId)`: Same pattern as addMute but for blocks endpoint and blockedIds set.

5. `removeBlock(targetCharacterId)`: Same pattern as removeMute but for blocks endpoint and blockedIds set.

6. `isMuted(id)` / `isBlocked(id)`: Simple `get().mutedIds.has(id)` / `get().blockedIds.has(id)`.

7. `reset()`: Clear both sets, set loaded to false.

**Important implementation notes:**
- Use `import { apiCall } from '../utils/api'` for REST calls
- Use `import { useGameStore } from './gameStore'` for player.id access
- Sets must be recreated (not mutated) in Zustand: `new Set([...state.mutedIds, targetCharacterId])` pattern
- The REST API response types from the database package won't be directly importable in the web app. Instead, type the API responses inline as `{ mutedCharacterId: string }[]` and `{ blockedCharacterId: string }[]` (just the fields we need).
- Export `useModerationStore` as the main hook.

**Auto-load via side-effect import:**
At the bottom of moderationStore.ts, add a module-level listener that calls `loadModeration` when the gameStore player becomes available:

```typescript
// Auto-load moderation state when player is set (game session starts)
// Uses Zustand subscribe to react to player state changes
const unsubscribe = useGameStore.subscribe(
  (state) => state.player,
  (player, prevPlayer) => {
    if (player && !prevPlayer) {
      useModerationStore.getState().loadModeration();
    }
    if (!player && prevPlayer) {
      useModerationStore.getState().reset();
    }
  }
);
```

Wait — Zustand's default `subscribe` does NOT support selectors with two args like that. Instead, use the pattern: subscribe to the full state and check player changes manually, OR use Zustand's `subscribeWithSelector` middleware. Since the codebase doesn't use that middleware, use a simpler approach:

```typescript
// Module-level: subscribe to gameStore and load moderation when player appears
useGameStore.subscribe((state) => {
  const player = state.player;
  const { loaded, loadModeration, reset } = useModerationStore.getState();
  if (player && !loaded) {
    loadModeration();
  }
});
```

This will call loadModeration once when player is set and loaded is false. The `loaded` flag prevents re-fetching on every gameStore state change.
