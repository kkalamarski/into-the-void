# Plan 130-01: Remove PNG Tile Loading and Dead Code

## Goal

Delete all dead PNG tile loading code from PreloadScene, remove dead code paths from TileRenderer and WorldScene, fix the stale texture key fallback, and archive tile PNG files. After this plan, zero tile PNG assets will be loaded at runtime.

## Context

Phase 126 replaced PNG tile sprites with procedural cubes baked via `ProceduralTileGenerator`. The PNG tile loading method `loadFloorTileSprites()` was commented out in Phase 126 but not deleted. Several related methods in TileRenderer and WorldScene are now dead code. This plan performs the surgical removal.

**Key constraint from CONTEXT.md:** Clean break — no debug flag or fallback mechanism to re-enable PNG tile rendering. If a tile type has no procedural definition, render a default gray cube.

## Tasks

<task id="1">
### Task 1: Delete PNG tile loading from PreloadScene

**File:** `apps/web/src/game/scenes/PreloadScene.ts`

**Steps:**

1. **Delete the commented-out call** at line 55-56:
   ```
   // Floor tile sprites replaced by procedural generation in create()
   // PNG loading disabled — procedural cubes replace all tile PNGs
   // this.loadFloorTileSprites();
   ```
   Replace these 3 lines with a single comment:
   ```typescript
   // Tile textures baked procedurally in create() via ProceduralTileGenerator
   ```

2. **Delete the entire `loadFloorTileSprites()` method** (lines 309-361). This method loads:
   - Floor tiles with variants (`tile_toxic_floor`, `_v2`, `_v3`, etc.)
   - Void/crystal tile spritesheets (`void-tiles.png`, `crystal-tiles.png`)
   - Feature tiles (`tile_toxic_pool`, `tile_ruins_wall`, etc.)
   - Quest marker PNGs (`ui_quest_marker_available`, `ui_quest_marker_ready`)

   **IMPORTANT:** The quest marker loading (lines 359-360) is inside this dead method. These are NOT tile PNGs but UI assets. Move them to the `loadAssets()` method before deleting `loadFloorTileSprites()`. Add them after `this.loadItemSpritesheets();`:
   ```typescript
   // Quest marker sprites (UI elements, not tiles)
   this.load.image('ui_quest_marker_available', 'sprites/ui_quest_marker_available.png');
   this.load.image('ui_quest_marker_ready', 'sprites/ui_quest_marker_ready.png');
   ```

3. **Clean up `extractSpritesheetFrames()`** — Remove only the tile-related extraction blocks. Keep the feature spritesheet extraction.

   **Delete these blocks:**
   - The `voidTileMap` block (lines 553-557) that extracts `tile_void_floor` and `tile_void_wall` from `void-tiles-sheet`
   - The `crystalTileMap` block (lines 560-566) that extracts `tile_crystal_floor`, `tile_crystal_floor_v2`, `tile_crystal_formation`, `tile_crystal_formation_v2` from `crystal-tiles-sheet`

   **Keep these blocks (feature spritesheets — still active):**
   - `voidFeatureMap` extraction from `void-biome-features-sheet`
   - `crystalFeatureMap` extraction from `crystal-biome-features-sheet`
   - `acidFeatureMap` extraction from `acid-biome-features-sheet`

4. **Remove stale JSDoc comments** — The `generateTileTextures()` method has this comment on line 367:
   ```
   // All tile textures now loaded from PNG - only generate entity textures
   ```
   Update to:
   ```typescript
   // Procedural tile textures baked in create() — this generates entity fallback textures
   ```

**Verification:**
- `loadFloorTileSprites` does not exist in the file
- No `this.load.image('tile_` or `this.load.spritesheet('void-tiles` or `this.load.spritesheet('crystal-tiles` calls remain
- Quest marker loading (`ui_quest_marker_available`, `ui_quest_marker_ready`) is preserved in `loadAssets()`
- Feature spritesheet extraction (void-biome-features, crystal-biome-features, acid-biome-features) still present in `extractSpritesheetFrames()`
</task>

### Task 2: Remove dead code from TileRenderer and WorldScene

**File 1:** `apps/web/src/game/rendering/TileRenderer.ts`

**Steps:**

1. **Fix the stale fallback key** in `getTextureKey()` (line 97):
   ```typescript
   // Before:
   return TILE_TEXTURE_MAP[tileId] ?? 'tile_void_floor';
   // After:
   return TILE_TEXTURE_MAP[tileId] ?? 'proc_tile_void_floor';
   ```

2. **Delete `isValidCubeTexture()` method** (lines 104-112). It is a private method not called by any active code path.

3. **Delete `createTile()` method** (lines 118-150). This creates a flat diamond polygon without elevation — only used by the dead `WorldScene.loadZone()` method. The JSDoc says "placeholder until isometric sprites are available" — sprites are available now (procedural cubes).

4. **Delete `createTileWithElevation()` method** (lines 180-223). This is the non-world-coordinate variant. Only `createTileWithElevationWorld()` is used by `renderChunk()`. Verify no other callers exist by searching for `createTileWithElevation(` (without `World`).

5. **Remove stale comment** from `createCubeSprite()` JSDoc: the comment `Floor tiles have variants (_v2, _v3) selected deterministically by position seed.` on line 385 should be updated to remove reference to "floor tiles" specifically — all procedural tiles with `_floor` suffix have variants.

**File 2:** `apps/web/src/game/scenes/WorldScene.ts`

**Steps:**

1. **Delete `loadZone()` method** (lines 1462-1479). This is a legacy method for loading zones without chunk management. Search confirms it is defined but never called from outside.

2. **Clean up `tileSprites` array reference** — If `tileSprites` is only used by `loadZone()`, delete the property declaration too. Search for `tileSprites` to verify all usages.

**Verification:**
- `isValidCubeTexture` does not exist in TileRenderer.ts
- `createTile` (the flat version without elevation) does not exist in TileRenderer.ts
- `createTileWithElevation` (without World suffix) does not exist in TileRenderer.ts
- `loadZone` does not exist in WorldScene.ts
- `getTextureKey()` fallback references `proc_tile_void_floor`
- `createTileWithElevationWorld()` and `createCubeSprite()` still exist and function correctly
- `createFallbackCube()` still exists (gray cube fallback per CONTEXT.md)
</task>
