<objective>
Create the NestJS REST API module for mute/block CRUD operations with JWT-protected endpoints.

Purpose: The client needs to persist mute/block lists across sessions. This plan creates the REST endpoints that the client (Phase 107) will call to add/remove/list muted and blocked players. The endpoints also validate character ownership to prevent one player from managing another player's moderation lists.

Output: A complete `ModerationModule` with controller, service, and DTOs wired into the API's `AppModule`.

2. **Create `apps/api/src/moderation/moderation.service.ts`**:

   Injectable service with constructor injection of `DatabaseService`. Import query functions from `@into-the-void/database`:
   - `addMute`, `removeMute`, `getMutes`, `addBlock`, `removeBlock`, `getBlocks`, `isCharacterOwnedByAccount`

   Methods (all accept `accountId: string` as first param for ownership verification):

   - `async addMute(accountId: string, characterId: string, targetCharacterId: string)`:
     1. Verify `characterId` belongs to `accountId` using `isCharacterOwnedByAccount`. Throw `ForbiddenException` if not.
     2. Prevent self-mute: if `characterId === targetCharacterId`, throw `BadRequestException('Cannot mute yourself')`.
     3. Call `addMute(db, characterId, targetCharacterId)` and return the result.

   - `async removeMute(accountId: string, characterId: string, targetCharacterId: string)`:
     1. Verify ownership. Throw `ForbiddenException` if not.
     2. Call `removeMute(db, characterId, targetCharacterId)`.

   - `async getMutes(accountId: string, characterId: string)`:
     1. Verify ownership. Throw `ForbiddenException` if not.
     2. Call `getMutes(db, characterId)` and return the array.

   - `async addBlock(accountId: string, characterId: string, targetCharacterId: string)`:
     1. Verify ownership. Throw `ForbiddenException` if not.
     2. Prevent self-block: if `characterId === targetCharacterId`, throw `BadRequestException('Cannot block yourself')`.
     3. Call `addBlock(db, characterId, targetCharacterId)` and return the result.

   - `async removeBlock(accountId: string, characterId: string, targetCharacterId: string)`:
     1. Verify ownership. Throw `ForbiddenException` if not.
     2. Call `removeBlock(db, characterId, targetCharacterId)`.

   - `async getBlocks(accountId: string, characterId: string)`:
     1. Verify ownership. Throw `ForbiddenException` if not.
     2. Call `getBlocks(db, characterId)` and return the array.

   Follow the existing `CharactersService` pattern exactly: `this.databaseService.getClient()` for DB access.

3. **Create `apps/api/src/moderation/moderation.controller.ts`**:

   ```typescript
   @Controller('moderation')
   @UseGuards(JwtAuthGuard)
   export class ModerationController {
     constructor(private readonly moderationService: ModerationService) {}
   ```

   Six endpoints:

   - `POST /moderation/mutes` — Body: `CreateMuteDto`. Calls `this.moderationService.addMute(req.user.accountId, dto.characterId, dto.targetCharacterId)`. Returns the created mute entry.

   - `GET /moderation/mutes/:characterId` — Param: `characterId` (ParseUUIDPipe). Calls `this.moderationService.getMutes(req.user.accountId, characterId)`. Returns array of mute entries.

   - `DELETE /moderation/mutes/:characterId/:targetCharacterId` — Params: both with ParseUUIDPipe. Calls `this.moderationService.removeMute(...)`. Returns `{ message: 'Mute removed' }`.

   - `POST /moderation/blocks` — Body: `CreateBlockDto`. Same pattern as mutes.

   - `GET /moderation/blocks/:characterId` — Same pattern as mutes GET.

   - `DELETE /moderation/blocks/:characterId/:targetCharacterId` — Same pattern as mutes DELETE. Returns `{ message: 'Block removed' }`.

   Use `@Request() req: { user: { accountId: string } }` on every method (same pattern as CharactersController).
