Rewrite `apps/game-server/src/game/game.gateway.ts` to delegate all event handling to the 5 handler classes.

**Structure of the new gateway:**

1. **Imports:** Import handler classes from `./handlers`, plus only the services still needed directly (PlayerService, GameService, InventoryService, AbilityService, GatheringService, CraftingService, CombatService, MovementService, AiService, HazardService, AutomationService, DiscoveryService, EventEmitter2, ZonesService). Import Socket.IO and NestJS WebSocket decorators.

2. **Constructor:** Inject the 5 handlers + the services listed above. Remove services that are ONLY used in extracted handlers (TradeService, QuestService, LoreService, ZoneMasteryService, ExpeditionService, ChatService, EntityService, StorageService).

3. **afterInit(server):**
   - Call `setServer(server)` on all 5 handlers
   - Keep existing setServer calls for services that need it (zonesService, aiService, combatService, playerService, abilityService, questService — wait, questService is no longer injected. Only call setServer on services still injected in the gateway)
   - Actually: services that had setServer called but are now only used inside handlers should have their setServer called FROM the handler's own afterInit or from the handler's setServer method. BUT the simplest approach: keep calling setServer on all original services from afterInit (they're still NestJS singletons — the gateway can inject them just for init). HOWEVER, to keep the gateway slim, the better approach is:
   - Call setServer on the 5 handlers (handlers call setServer on their own injected services internally if needed — but actually services don't need setServer called twice). The problem is services like QuestService, LoreService, etc. need setServer called once. Since they're no longer injected in the gateway, their setServer must be called from the handler that owns them.
   - **Solution:** Each handler's `setServer(server)` method should also call `setServer(server)` on its injected services that need it. Specifically:
     - ZoneHandler.setServer: calls zonesService.setServer, aiService.setServer, also sets zonesService.setAggroChecker(aiService)
     - InventoryHandler.setServer: (no services need server)
     - CombatHandler.setServer: calls combatService.setServer, abilityService.setServer
     - SocialHandler.setServer: calls questService.setServer, loreService.setServer, zoneMasteryService.setServer, expeditionService.setServer, chatService.setServer
     - AutomationHandler.setServer: calls automationService.setServer
   - Gateway afterInit then: calls setServer on 5 handlers + playerService.setServer + movementService.setServer + hazardService.setServer + playerService.setZoneStateProvider
   - This means Plan 01 handlers need their setServer methods to propagate to child services. **Add this propagation to each handler's setServer method.**

4. **handleConnection(client):** Keep as-is (auth timeout logic, ~15 lines).

5. **handleDisconnect(client):** Keep as-is (~25 lines). This still needs direct service calls for cleanup.

6. **handleAuth(client, data):** Keep the full auth handler (~110 lines) since it orchestrates across many domains (loads inventory, activates AI, sends zone state, emits stats, etc.). Replace helper calls:
   - `this.updatePlayerRooms(...)` → `this.zoneHandler.updatePlayerRooms(...)`
   - `this.emitStats(...)` → `this.inventoryHandler.emitStats(...)`
   - `this.resolveZoneBiome(...)` → `this.zoneHandler.resolveZoneBiome(...)`
   - `this.emitNpcQuestMarkers(...)` → `this.zoneHandler.emitNpcQuestMarkers(...)`

7. **All other @SubscribeMessage handlers become thin delegators:**

```typescript
@SubscribeMessage('player:pixelMove')
handlePixelMove(@ConnectedSocket() client: Socket, @MessageBody() data: { keys: number; predictedPx: number; predictedPy: number; sequence: number }) {
  const player = this.playerService.getPlayerBySocket(client.id);
  if (!player) return;
  if (this.abilityService.isPlayerCasting(player.id)) {
    this.abilityService.interruptCast(player.id, 'moved');
  }
  this.movementService.queueInput(player.id, data);
  this.gatheringService.cancelIfOutOfRange(player.id, data.predictedPx, data.predictedPy);
}

@SubscribeMessage('player:interact')
handleInteract(@ConnectedSocket() client: Socket, @MessageBody() data: ClientEvents['player:interact']) {
  return this.inventoryHandler.handleInteract(client, data);
}

@SubscribeMessage('chat:send')
handleChat(@ConnectedSocket() client: Socket, @MessageBody() data: ClientEvents['chat:send']) {
  return this.socialHandler.handleChat(client, data);
}

@SubscribeMessage('ping')
handlePing(@MessageBody() timestamp: number): number { return timestamp; }

@SubscribeMessage('zone:request')
handleZoneRequest(@ConnectedSocket() client: Socket, @MessageBody() data: any) {
  return this.zoneHandler.handleZoneRequest(client, data);
}
```
