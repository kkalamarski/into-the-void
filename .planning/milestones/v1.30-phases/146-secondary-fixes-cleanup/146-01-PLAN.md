# Plan 146-01: Fix portal debounce key and NPC proximity pixel position

## Context

Two bugs in `apps/web/src/game/scenes/WorldScene.ts`:

### Bug 1: Portal debounce key missing zoneId (MISC-01)

The `checkPortalTileAtPixels` method (line ~2263) builds a debounce key as:
```ts
const key = `${tileX},${tileY}`;
```
This key does NOT include the current zone ID. When a player uses a portal (e.g., at tile 5,5 in hub zone) and arrives in a new zone where another portal exists at the same tile coordinates (5,5), the debounce key matches and the second portal is suppressed.

The older `checkPortalTile` method (line ~649) correctly includes zoneId:
```ts
const posKey = `${position.x},${position.y},${position.zoneId}`;
```
But `checkPortalTileAtPixels` was added later for the pixel movement path and omitted zoneId.

**Fix:** Include `this.currentZoneId` in the debounce key for `checkPortalTileAtPixels`.

### Bug 2: NPC proximity uses tile-center approximation on old path (MISC-02)

The `updateLocalPlayerSprite` method (tile-based position path, line ~2108) computes the player's pixel position via:
```ts
const { px: playerPx, py: playerPy } = tileToPixelCenter(position.x, position.y);
```
This snaps the player to the center of their current tile, which is an approximation. The pixel movement path (`updateLocalPlayerFromPixels`, line ~2207) correctly passes the actual `px, py` values.

When the tile-based path is active (e.g., after teleportation via `updateLocalPlayerSprite`), the NPC proximity check sees the player at tile center instead of their actual position. The player's actual pixel position is stored in `useGameStore.getState().player?.px` and `py` fields.

**Fix:** In `updateLocalPlayerSprite`, read the player's actual pixel position from the game store (if available) instead of converting tile coords to tile center. If px/py are not available (defensive), fall back to `tileToPixelCenter`.

## Tasks

### Task 1: Fix portal debounce key to include zoneId

**File:** `apps/web/src/game/scenes/WorldScene.ts`

In the `checkPortalTileAtPixels` method (~line 2263-2275):

1. Change the key construction from:
   ```ts
   const key = `${tileX},${tileY}`;
   ```
   to:
   ```ts
   const key = `${this.currentZoneId}:${tileX},${tileY}`;
   ```

2. Also clear `this.lastPortalEmitKey` when the zone changes. In the `fullZoneReset` method (~line 1264), add:
   ```ts
   this.lastPortalEmitKey = null;
   ```
   after the existing `this.pendingZoneId = null;` and `this.pendingBiome = null;` lines. This ensures the debounce is always cleared on teleportation, so the player can use a portal immediately in the new zone.

3. In `commitZoneTransition` (~line 1136), also clear the portal debounce:
   ```ts
   this.lastPortalEmitKey = null;
   ```
   Add this after the `this.currentZoneId = newZoneId;` line. This handles seamless world zone transitions where a portal exists near the boundary.

### Task 2: Fix NPC proximity to use actual pixel position

**File:** `apps/web/src/game/scenes/WorldScene.ts`

In the `updateLocalPlayerSprite` method (~line 2107-2110), replace:
```ts
const { px: playerPx, py: playerPy } = tileToPixelCenter(position.x, position.y);
this.updateRangeIndicator(playerPx, playerPy);
this.updateNpcProximity(playerPx, playerPy);
```
with:
```ts
const playerState = useGameStore.getState().player;
const playerPx = playerState?.px ?? tileToPixelCenter(position.x, position.y).px;
const playerPy = playerState?.py ?? tileToPixelCenter(position.x, position.y).py;
this.updateRangeIndicator(playerPx, playerPy);
this.updateNpcProximity(playerPx, playerPy);
```

This reads the actual sub-tile pixel position if available, falling back to tile-center only when px/py are not set (e.g., initial load before first pixel movement tick).

## Verification

1. **Portal debounce**: After the fix, `checkPortalTileAtPixels` builds keys like `"hub_verdant:5,5"` instead of `"5,5"`. The key changes when the player enters a new zone, so a portal at the same tile coords in the new zone is NOT debounced.
2. **Zone transition clears debounce**: Both `commitZoneTransition` and `fullZoneReset` clear `lastPortalEmitKey = null`, so any portal in the destination zone can trigger immediately.
3. **NPC proximity**: The `updateLocalPlayerSprite` path now reads real pixel coords from the store, matching the behavior of `updateLocalPlayerFromPixels`. Both paths pass the same coordinate source to `updateNpcProximity`.
4. **Build passes**: `npx nx run web:build` completes with no errors.
